# miniproject_4: RTC DS1307 + OLED SSD1306 + меню — дизайн

Дата: 2026-09-27
База: `C:\embedded\miniproject_3\miniproject_3` (автоматична годівничка на ESP32-S3-N16R8, ESP-IDF v6.0.2)

## 1. Мета

Розширити годівничку з miniproject_3:

1. Підключити RTC DS1307 (I2C) і встановлювати в нього локальний час.
2. Підключити OLED SSD1306 128×64 (I2C, 0.96"), який показує час, рівень порції
   та відлік до наступної автоподачі, і реалізувати меню керування енкодером.

Механіка годування (зумер → серво → мотор → серво), NVS-збереження порції та AUTO,
квадратурний декодер енкодера — без змін.

## 2. Апаратна частина

### 2.1 Розпіновка

Змінюється лише те, що в таблиці; решта як у miniproject_3.

| Сигнал | GPIO | Статус |
|---|---|---|
| I2C SDA (RTC + OLED) | 18 | нове |
| I2C SCL (RTC + OLED) | 3 | нове |
| KY-040 SW (клік енкодера) | 6 | тепер використовується |
| Кнопка GPIO8 | 8 | була «AUTO toggle», тепер «Назад» |

Без змін: енкодер CLK/DT = 4/5, ручна подача = 7, LED порції = 9–12,
LED AUTO (червоний) = 13, LED FEEDING (зелений) = 14, зумер = 15, серво = 16, мотор = 17.

GPIO46 (теж вільний) під I2C **не використовується**: це strapping-пін режиму
завантаження, і підтяжка до високого рівня разом з GPIO0=0 дає недопустиму комбінацію
при вході в режим прошивки. GPIO3 — strapping лише для вибору джерела JTAG (через eFuse),
для I2C безпечний.

### 2.2 Адреси на шині I2C

| Пристрій | Адреса |
|---|---|
| OLED SSD1306 | 0x3C |
| AT24C32 EEPROM (на модулі RTC) | 0x50 — не використовується |
| DS1307 | 0x68 |

Шина одна, 100 кГц.

### 2.3 Живлення модуля RTC (Tiny RTC, без батарейки)

На модулі SDA/SCL підтягнуті резисторами R2/R3 (4.7 кОм) до VCC модуля. DS1307 за
даташитом потребує VCC 4.5–5.5 В. Випаювати нічого не будемо. Варіанти за порядком спроб:

1. **VCC модуля = 3.3 В.** Шина 3.3 В, безпечно для ESP32. DS1307 працює поза
   специфікацією і може не відповідати — прошивка це переживає (`--:--`).
2. **VCC = 5Vin + перетворювач рівнів BSS138** — коректний варіант.
3. **VCC = 5Vin напряму** — на шині ~4–4.2 В, що вище абсолютного максимуму ESP32-S3
   (3.6 В); свідомий ризик користувача.

Прошивка однакова для всіх варіантів. Батарейки немає, тому при зникненні живлення
DS1307 втрачає час. Якщо колись ставити батарейку — лише LIR2032 (на модулі є ланцюг
заряджання) і лише при VCC = 5 В (при 3.3 В поріг power-fail ≈1.25·VBAT блокує I2C).

## 3. Архітектура

### 3.1 Модулі (`main/`)

| Модуль | Статус | Відповідальність |
|---|---|---|
| `buzzer`, `servo`, `motor`, `leds`, `encoder` | без змін | як у miniproject_3 |
| `buttons` | змінений | 3 кнопки з дебаунсом: `manual` (GPIO7), `enc_click` (GPIO6), `back` (GPIO8) |
| `settings` | змінений | + рядок мітки збірки в NVS (`build_stamp`) |
| `feeder` | змінений | нові події, стан меню, публікація знімка стану |
| `i2c_bus` | новий | один `i2c_master_bus`, хендли пристроїв, скан шини в лог |
| `rtc_ds1307` | новий | читання/запис часу, CH, 24h, RAM модуля, BCD |
| `oled` | новий | `esp_lcd` SSD1306 (`esp_lcd_new_panel_io_i2c` + `esp_lcd_new_panel_ssd1306`), кадровий буфер 128×64, `oled_clear`, `oled_draw_text`, `oled_invert_rect`, `oled_flush` |
| `font8x16.h` | новий | моноширинний шрифт 8×16, ASCII 0x20–0x7E |
| `menu` | новий | чиста логіка станів меню, без заліза, тестується на ПК |
| `ui` | новий | формування рядків і малювання екранів зі знімка стану |
| `build_time.h` | генерований | мітка часу збірки (див. 5.1) |

Сторонніх компонентів немає: лише ESP-IDF (`esp_driver_i2c`, `esp_lcd`, `nvs_flash`,
`esp_timer`, `esp_driver_gpio`, `esp_driver_ledc`).

### 3.2 Події

```c
typedef enum {
    EVT_ENCODER_DELTA,  /* поворот, value = +1/-1 (з ISR) */
    EVT_ENC_CLICK,      /* клік енкодера (GPIO6) */
    EVT_BTN_BACK,       /* кнопка «Назад» (GPIO8) */
    EVT_BTN_MANUAL,     /* ручна подача (GPIO7) */
    EVT_AUTO_TIMER,     /* спрацював таймер автоподачі */
} event_type_t;
```

`EVT_BTN_AUTO_TOGGLE` прибирається.

### 3.3 Задачі

- **`input_task`** (опитування кожні 10 мс) — три кнопки → події в `event_queue`.
  Енкодер шле `EVT_ENCODER_DELTA` з ISR, як раніше.
- **`feeder_task`** — єдиний власник стану: підтверджена порція, `auto_enabled`,
  стан меню, прапорець `feeding`. Передає події в `menu`, виконує повернуті дії
  (LED, NVS, таймер, `feed_cycle`). Після кожної зміни публікує знімок стану під м'ютексом.
- **`display_task`** (новий, період ~200 мс) — копіює знімок стану, раз на секунду читає
  RTC, рахує відлік як `esp_timer_get_expiry_time(auto_timer) − esp_timer_get_time()`
  (округлення вгору до секунд), малює кадр. **Єдина задача, що працює з I2C** —
  блокувань шини не потрібно. Екран оновлюється і під час блокуючого `feed_cycle()`.

### 3.4 Знімок стану для дисплея

```c
typedef struct {
    ui_screen_t screen;       /* MAIN, MENU_ROOT, MENU_PORTION, MENU_AUTO */
    uint8_t     cursor;       /* курсор у MENU_ROOT / MENU_AUTO */
    uint8_t     portion;      /* підтверджена порція */
    uint8_t     preview;      /* рівень попереднього перегляду в MENU_PORTION */
    bool        auto_enabled;
    bool        feeding;
} ui_state_t;
```

Доступ через `ui_state_publish()` / `ui_state_get()` з м'ютексом. Хендл автотаймера
для обчислення відліку `feeder` надає через функцію `auto_timer_remaining_sec(int *sec)`
(повертає false, якщо таймер не запущений).

## 4. Екрани та меню

Шрифт 8×16 → 16 символів × 4 рядки. Курсор меню — інвертований рядок на всю ширину.

### 4.1 Головний екран

```
┌────────────────┐
│                │
│14:37   3    27s│
│                │
│                │
└────────────────┘
```

- Рядок стану — у 2-му рядку (y = 16).
- Ліворуч `HH:MM` (24h) або `--:--`, якщо час невалідний.
- По центру підтверджена порція `1`–`4`.
- Праворуч відлік `<N>s`, вирівняний праворуч, до 6 символів; порожньо, якщо AUTO вимкнено.
- Поворот енкодера і «Назад» — нічого. Клік → кореневе меню, курсор на `Portion`.

### 4.2 Кореневе меню

```
│MENU            │
│▓Portion       ▓│
│ Auto Mode      │
```

- Поворот рухає курсор між двома пунктами, без зациклення (clamp).
- Клік → відповідне підменю.
- «Назад» → головний екран.

### 4.3 Portion

```
│Portion         │
│                │
│  1  2 ▓3▓ 4    │
```

- При вході `preview = portion`.
- Поворот: `preview = clamp(preview ± 1, 1, 4)`, сині LED одразу показують `preview`.
- Клік: `portion = preview`, запис у NVS, повернення в кореневе меню (курсор на `Portion`).
- «Назад»: LED повертаються на `portion`, повернення в кореневе меню без змін.

### 4.4 Auto Mode

```
│Auto Mode       │
│▓* Enabled     ▓│
│  Disabled      │
```

- `*` позначає фактичний поточний режим; курсор при вході стоїть на поточному режимі.
- Поворот рухає курсор (clamp).
- Клік: якщо вибір відрізняється від поточного — застосувати (червоний LED, NVS;
  Enabled → старт таймера з повного інтервалу, Disabled → стоп таймера); якщо той самий —
  нічого не змінювати і таймер не перезапускати. Далі — кореневе меню (курсор на `Auto Mode`).
- «Назад» → кореневе меню без змін.

### 4.5 Насипання

Запускається кнопкою GPIO7 з будь-якого екрана або таймером (лише якщо AUTO увімкнено).

```
│14:37   2    30s│
│                │
│   FEEDING...   │
│                │
```

- Рядок стану переїжджає в 1-й рядок, по центру `FEEDING...`.
- Насипається **підтверджена** порція. Під час циклу сині LED показують її, зелений LED горить.
- Ввід під час циклу ігнорується: після циклу `xQueueReset(event_queue)`, як у miniproject_3.
- Після циклу повертається той самий екран зі збереженим станом. Якщо це було меню Portion
  з непідтвердженим вибором — LED знову показують `preview`.

### 4.6 Контракт модуля `menu`

Чиста функція переходу, без заліза:

```c
menu_action_t menu_handle(ui_state_t *st, event_type_t evt, int8_t value);
```

`menu_handle` сама оновлює поля `st` (екран, курсор, `preview`, `portion`, `auto_enabled`)
і повертає `menu_action_t { type; arg; }` — побічний ефект, який виконує `feeder_task`:

| `type` | `arg` | Що робить `feeder_task` |
|---|---|---|
| `ACT_NONE` | — | нічого |
| `ACT_SHOW_LEDS` | рівень 1–4 | `update_portion_leds(arg)` (перегляд або відкат) |
| `ACT_COMMIT_PORTION` | рівень 1–4 | `update_portion_leds(arg)` + `settings_set_portion(arg)` |
| `ACT_SET_AUTO` | 0/1 | LED AUTO, `settings_set_auto_enabled`, старт/стоп таймера |
| `ACT_FEED` | — | `feed_cycle(st->portion)`, потім відновити LED (`preview` у MENU_PORTION, інакше `portion`) |

`EVT_BTN_MANUAL` дає `ACT_FEED` з будь-якого екрана; `EVT_AUTO_TIMER` — лише якщо
`st->auto_enabled`, інакше `ACT_NONE`. Прапорець `feeding` виставляє `feeder_task`
навколо `feed_cycle()`, а не `menu`.

## 5. RTC і встановлення часу

### 5.1 Мітка збірки

- На **кожну** збірку CMake (custom command, що завжди виконується) генерує
  `build_time.h` у каталозі збірки з локальним часом ПК: `BUILD_YEAR`, `BUILD_MONTH`,
  `BUILD_DAY`, `BUILD_HOUR`, `BUILD_MIN`, `BUILD_SEC`, `BUILD_STAMP` (рядок `YYYYMMDDhhmmss`).
- `__DATE__`/`__TIME__` не використовуються, бо оновлюються лише при перекомпіляції
  конкретного `.c`-файлу.
- `RTC_BUILD_OFFSET_SEC` у `config.h` (за замовчуванням 30) компенсує час між збіркою
  і стартом плати.

### 5.2 Маркер валідності

Після подачі живлення без батарейки регістри DS1307 не визначені (CH може бути 0,
час — сміття). Тому валідність підтверджується 4-байтовим маркером у RAM DS1307
(0x08–0x0B), який живе, поки модуль має живлення.

### 5.3 Алгоритм при старті

1. DS1307 не відповідає на 0x68 → час невалідний (`--:--`), попередження в лог.
2. `BUILD_STAMP` ≠ мітки в NVS (перший старт нової прошивки) → записати час збірки + offset,
   24h режим, CH = 0, записати маркер у RAM, зберегти `BUILD_STAMP` у NVS → час валідний.
3. Інакше, якщо маркер не збігається, або CH = 1, або BCD некоректний → час невалідний
   (`--:--`) до наступної прошивки.
4. Інакше → час валідний.

### 5.4 Під час роботи

- `display_task` читає регістри 0x00–0x06 раз на секунду.
- Невдале читання або некоректні дані → `--:--` для цього кадру; наступне успішне читання
  знову показує час (якщо на старті стан визнано валідним).
- Стан «невалідний» зі старту (п. 3) лишається до наступної прошивки.

### 5.5 Часовий пояс

RTC зберігає локальний час (час ПК при збірці). Перехід на літній/зимовий час
не обробляється — після переходу потрібна перепрошивка.

## 6. Обробка помилок

| Ситуація | Поведінка |
|---|---|
| Помилка конфігурації I2C-шини | `ESP_ERROR_CHECK` → abort (баг прошивки) |
| OLED не відповідає при ініціалізації | попередження в лог, `display_task` не малює; решта працює |
| Помилка запису на OLED під час роботи | пропустити кадр |
| RTC відсутній / сміття | `--:--`, читання тривають щосекунди |
| NVS недоступний | значення за замовчуванням, як у miniproject_3 |
| Переповнення черги подій | подія губиться (`xQueueSend` з таймаутом 0), як у miniproject_3 |

На старті — скан шини I2C у лог (очікувано `0x3C`, `0x50`, `0x68`).

## 7. Тестування

1. **Модульні тести на ПК (TDD)** — `gcc` з msys64 + Unity з ESP-IDF
   (`C:/esp/v6.0.2/esp-idf/components/unity/unity/src`), каталог `test/host/`, запуск одним
   скриптом. Покриття:
   - `menu`: усі переходи й дії з розділу 4;
   - `rtc_ds1307`: BCD кодування/декодування, перевірка коректності полів, CH;
   - розбір мітки збірки + offset (з переносом через хвилину/годину/добу/місяць);
   - `ui`: формування рядка стану (`HH:MM`/`--:--`, порція, відлік, порожнє праворуч,
     вирівнювання), рядка шкали Portion, рядків Auto Mode з `*`.
   Для тестованості `rtc_ds1307` і `ui` розділяють чисту логіку і I2C/малювання.
2. **Збірка** — `idf.py build` без помилок і попереджень.
3. **Ручний чекліст на платі** (виконує користувач):
   - скан I2C показує очікувані адреси;
   - після прошивки показано правильний час;
   - після вимкнення/увімкнення живлення — `--:--`;
   - усі переходи меню; «Назад» у Portion скасовує вибір і LED;
   - червоний LED відповідає AUTO; відлік іде і зникає при Disabled;
   - GPIO7 з меню → FEEDING → повернення в те саме меню;
   - автоподача під час відкритого меню → FEEDING підтвердженою порцією → повернення.
